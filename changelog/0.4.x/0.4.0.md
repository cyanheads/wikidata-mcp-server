# 0.4.0 — 2026-11-15

## Breaking

- **`wikidata_sparql_query` output:** `returnedCount` is removed, `totalCount` is optional (absent on a capped result), and `truncated` becomes an optional flag meaning the 4,000-row ceiling applied, beside `shown` and `cap`; a result body past 8 MiB fails as `result_too_large`. ([#51](https://github.com/cyanheads/wikidata-mcp-server/issues/51))

## Added

- **`wikidata_get_statements` paging:** `limit` (default 10, at most 500 per property) and `offset` window each property's statements in upstream order; `propertyTotals`, `returnedCount`, and `nextOffset` report the counts and the offset that continues every property. ([#45](https://github.com/cyanheads/wikidata-mcp-server/issues/45))
- **`wikidata_get_statements` `rank: "best"`** keeps each property's preferred statements, else its normal ones, never deprecated ones: the statements SPARQL's `wdt:` reads. `rank` is echoed in the output. ([#57](https://github.com/cyanheads/wikidata-mcp-server/issues/57))
- **`wikidata_get_statements` `propertyLabels`** maps the P-IDs of statements, qualifiers, reference parts, and property-typed values to labels, and `content[]` renders each beside its P-ID. ([#56](https://github.com/cyanheads/wikidata-mcp-server/issues/56))
- **`wikidata_resolve_external_id` `unavailableGraphs`** names a graph that did not answer within the shared 20 s deadline; the other graph's answer is returned with a notice, and the call fails only when both fail. ([#49](https://github.com/cyanheads/wikidata-mcp-server/issues/49))
- **`wikidata_resolve_external_id` `rank`** on `match` and each `multipleMatches` entry (`preferred`, `normal`, `deprecated`); a `deprecated` match is often a retired or mistaken ID. ([#50](https://github.com/cyanheads/wikidata-mcp-server/issues/50))
- **`wikidata_get_labels`** resolves up to 500 distinct IDs per call; `ids` takes up to 10,000 entries, the rest come back in `deferredIds`, and malformed entries in `invalid` instead of failing the call (`invalid_ids` only when none is valid). `languages` is limited to 50. ([#55](https://github.com/cyanheads/wikidata-mcp-server/issues/55))
- **Entity URIs and `wd:` IDs:** `wikidata_get_entity`, `wikidata_get_labels`, `wikidata_get_statements`, and `wikidata_get_sitelinks` accept `http://www.wikidata.org/entity/Q42` and `wd:Q42`, the forms SPARQL results carry. ([#55](https://github.com/cyanheads/wikidata-mcp-server/issues/55))
- **`wikidata_search_entities`** serves `limit` up to 500 and returns `nextOffset` (`offset + limit`) on every page that has results; `offset` is limited to 0–9,999. ([#53](https://github.com/cyanheads/wikidata-mcp-server/issues/53))
- **`WIKIDATA_CLAMP_LIMITS`** (default `true`): a count above its per-call cap is served at the cap with a notice; `false` rejects it, naming the cap. ([#45](https://github.com/cyanheads/wikidata-mcp-server/issues/45), [#51](https://github.com/cyanheads/wikidata-mcp-server/issues/51), [#53](https://github.com/cyanheads/wikidata-mcp-server/issues/53), [#55](https://github.com/cyanheads/wikidata-mcp-server/issues/55))

## Changed

- **`wikidata_get_statements`** returns at most 10 statements per property by default; `limit` and `offset` page the rest, and `propertyTotals` counts them. A single property is no longer returned whole. ([#45](https://github.com/cyanheads/wikidata-mcp-server/issues/45))
- **`wikidata_get_statements` labels:** when the label service is unavailable, rate-limiting, or past its deadline, the call returns its statements unlabelled with `labelsResolved: false` and a notice. In 0.3.0 the call failed.
- **`wikidata_sparql_query`** returns at most 4,000 rows per call, with or without a `LIMIT`; a larger result returns its first 4,000 and a notice to narrow, aggregate, or page with `ORDER BY`, `LIMIT`, and `OFFSET`. A body ending in the Query Service's timeout trailer fails as `timeout`. ([#51](https://github.com/cyanheads/wikidata-mcp-server/issues/51))
- **`wikidata_sparql_query` description and `wikidata-guide` skill 1.0 → 1.1** say scholarly articles are reachable only inside `SERVICE wdsubgraph:scholarly_articles { … }`, with their labels read inside that block. ([#49](https://github.com/cyanheads/wikidata-mcp-server/issues/49))
- **Framework:** `@cyanheads/mcp-ts-core` ^0.13.22, with its synced `framework-skills/`, `scripts/`, and `changelog/template.md`.

## Fixed

- **`WIKIDATA_SPARQL_TIMEOUT_MS`** now caps every SPARQL wait. In 0.3.0, `wikidata_sparql_query` always used its own `timeout` and ignored it.
- **A 400/422 HTML error page** from a proxy in front of the Query Service is ServiceUnavailable, named by its page title. 0.3.0 reported it as a SPARQL parse error quoting the page's markup.
- **A network failure** reaching the Query Service is ServiceUnavailable. In 0.3.0 it surfaced as an internal error.
- **SPARQL timeout messages** suggest narrowing the WHERE clause or adding or lowering the LIMIT. 0.3.0 always said to add a LIMIT, even to a query that had one.
- **`wikidata://entity/{id}` description** says what the resource renders: a label-language count with a five-language sample, and the number of properties with statements. 0.3.0 claimed every label and a statement count.
- **`wikidata_resolve_external_id` finds scholarly articles by DOI and PMID.** It queries the main and scholarly-article graphs in parallel, each reading its own labels; 0.3.0 queried only the main graph and returned `match: null` for every paper. ([#49](https://github.com/cyanheads/wikidata-mcp-server/issues/49))
- **`wikidata_resolve_external_id` matches identifiers at any rank**, taking the best rank tier that holds the value. 0.3.0 matched best-rank values only, so an ID on a normal-rank statement beside a preferred one, or held only at deprecated rank, returned `match: null`. ([#50](https://github.com/cyanheads/wikidata-mcp-server/issues/50))
- **`wikidata_resolve_external_id` normalizes resolver URLs and case** for OpenAlex, ORCID, DOI, PubMed, and IMDb IDs; an OpenAlex ID is also tried with its entity letter in the other case. 0.3.0 returned `match: null` for these forms. ([#54](https://github.com/cyanheads/wikidata-mcp-server/issues/54))
- **`wikidata_get_sitelinks` `wikis_only`** keeps only Wikipedia editions, those whose URL is on a `<subdomain>.wikipedia.org` host. 0.3.0 kept every site code ending in `wiki`, so Commons, Wikispecies, and other projects came back as Wikipedia. ([#52](https://github.com/cyanheads/wikidata-mcp-server/issues/52))
- **`wikidata_get_sitelinks` `sites`** matches in any case with whitespace trimmed, and an entry without a `url` renders as plain text. In 0.3.0 `ENWIKI` matched nothing, and `content[]` linked a URL built from the site code that `structuredContent` lacked. ([#52](https://github.com/cyanheads/wikidata-mcp-server/issues/52))
- **`wikidata_search_entities`** says the results ended before the offset when a page past the end is empty, and rejects an `offset` of 10,000 or more as invalid arguments. 0.3.0 reported that nothing matched, and offset 10,000 failed as a raw HTTP 500. ([#53](https://github.com/cyanheads/wikidata-mcp-server/issues/53))

## Security

- **Bounded SPARQL reads:** each `wikidata_sparql_query` call reads at most 4,001 bindings, then aborts the request, and a result body past 8 MiB fails as `result_too_large`. ([#51](https://github.com/cyanheads/wikidata-mcp-server/issues/51))
