# 0.1.15 — 2026-07-14

## Added

- **`isEntityNotFoundError(err)`** — exported from `wikidata-rest-service.ts`. One predicate for "this entity does not exist", reading `data.statusCode` and treating 404 and 400 alike; the four entity-addressed surfaces call it instead of hand-rolling the check.
- **`resolveLangValue(map, lang)`** — exported from `wikidata-rest-service.ts`. Reads a language-keyed REST map, falling back to the entity's `mul` (multilingual) entry.
- **`invalid_property`** — `wikidata_get_statements` error (`ValidationError`), thrown before the fetch when a `properties` entry is not `P`+digits.

## Changed

- **`languagefallback=1`** — set on every `wbgetentities` request, so a requested language with no label of its own resolves to the entity's `mul` value, still keyed by the requested code.
- **`docs/design.md`** — per-tool **Errors:** bullets reconciled to the declared `errors[]` contracts: `ValidationError` where the doc claimed `InvalidParams`, `RateLimited` for `throttled`, `not_an_item` documented, and `no_sitelinks` / `multiple_matches` dropped — neither is a failure mode ([#23](https://github.com/cyanheads/wikidata-mcp-server/issues/23)).
- **`bunfig.toml`** — installs gated behind a 3-day `minimumReleaseAge` (`@cyanheads/mcp-ts-core` excluded) and scanned by `@socketsecurity/bun-security-scanner`.
- **`Dockerfile`** — pins `oven/bun:1.3.14`, drops the `nodejs`/`npm` layer, and mounts Bun's install cache.
- **`package.json`** — `packageManager` `bun@1.3.2` → `bun@1.3.14`; `engines.bun` `>=1.3.2` → `>=1.3.0`, matching the documented floor.

## Fixed

- **`entity_not_found`** — `wikidata_get_entity`, `wikidata_get_statements`, `wikidata_get_sitelinks`, and `wikidata://entity/{id}` leaked the upstream REST URL and status for an out-of-range ID. The catch blocks tested `data.status`, which no reachable code path populates; `wikidata_get_sitelinks` and the resource were also missing the 400 branch entirely ([#13](https://github.com/cyanheads/wikidata-mcp-server/issues/13)).
- **`fetchLabels()`** — one out-of-range ID made `wbgetentities` reject the whole batch with a top-level `no-such-entity` error, collapsing `wikidata_get_labels` to `found: 0`. The named ID is now dropped and the remainder re-requested; any other top-level error throws instead of reporting nothing found ([#14](https://github.com/cyanheads/wikidata-mcp-server/issues/14)).
- **`filterLangs()`** — `wikidata_get_entity` dropped `mul`-sourced labels, descriptions, and aliases, rendering `Q76` as its own QID. Each requested language now resolves through `mul` and lands under the requested key. The `wikidata://entity/{id}` resource had the same gap in its header and description ([#15](https://github.com/cyanheads/wikidata-mcp-server/issues/15)).
- **`wikidata_get_labels`** — `format()` cut the language list to three with no total, leaving a `content[]`-only client unable to tell a complete result from a sample ([#19](https://github.com/cyanheads/wikidata-mcp-server/issues/19)).
- **`wikidata_get_entity`** — `format()` truncated descriptions and the alias language list with no total, unlike its sibling labels block ([#22](https://github.com/cyanheads/wikidata-mcp-server/issues/22)).
- **`wikidata_get_statements`** — a malformed `properties` entry silently vanished from a mixed batch and leaked a raw 400 on its own. Entries are validated before the fetch, which also keeps that 400 unambiguous for `entity_not_found` ([#24](https://github.com/cyanheads/wikidata-mcp-server/issues/24)).
