# 0.1.16 — 2026-07-14

## Added

- **`not_external_id_property`** — `wikidata_resolve_external_id` error (`ValidationError`), thrown before the SPARQL lookup when the property does not exist on Wikidata or its `data_type` is not `external-id` ([#16](https://github.com/cyanheads/wikidata-mcp-server/issues/16)).
- **`fetchPropertyDataType(id, ctx)`** — exported from `wikidata-rest-service.ts`. `GET /entities/properties/{id}?_fields=data_type`, ~40 bytes versus a full property payload.

## Changed

- **`wikidata_resolve_external_id`** — tool description and the `match` output field now note that a `null` result is not proof of absence, since the Query Service lags the live wiki.

## Fixed

- **`normalizeExternalId()`** — identifier-resolver URL prefixes (`https://doi.org/`, `https://dx.doi.org/`, a bare `doi:` scheme, `https://pubmed.ncbi.nlm.nih.gov/`, `https://orcid.org/`) are now stripped before the per-property normalization switch, so a copy-pasted resolver URL resolves instead of returning `match: null` ([#18](https://github.com/cyanheads/wikidata-mcp-server/issues/18)).
- **`normalizeId()`** — trims surrounding whitespace before the `Q`/`P` format check, so a padded `id`/`ids` value no longer fails validation across every tool and the `wikidata://entity/{id}` resource that inherit it. `wikidata_resolve_external_id`'s own inline `property` check gets the same trim directly ([#21](https://github.com/cyanheads/wikidata-mcp-server/issues/21)).
- **`normalizeExternalId()`** — `value` is now trimmed ahead of the resolver-prefix strip, closing the last padding gap: a padded DOI or IMDb ID previously reached the SPARQL literal intact and returned a confident `match: null` for an identifier that resolves ([#25](https://github.com/cyanheads/wikidata-mcp-server/issues/25)).
