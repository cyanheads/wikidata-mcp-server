# 0.1.6 — 2026-05-24

## Fixed

- **SPARQL label SERVICE injection** — regex in `WikidataSparqlService` now handles queries ending with solution modifiers (`LIMIT`, `OFFSET`, `ORDER BY`, `GROUP BY`, `HAVING`); previously the pattern `/\}\s*$/` matched only when `}` was the last character, silently skipping injection when a `LIMIT` clause followed ([#6](https://github.com/cyanheads/wikidata-mcp-server/issues/6)).
- **`wikidata_search_entities` description always empty** — handler read `r['display-description']?.value` but the REST v1 response field is `description`, not `display-description`; updated `RawSearchResult` type and handler mapping ([#7](https://github.com/cyanheads/wikidata-mcp-server/issues/7)).
- **400 for out-of-range IDs exposes internal URL** — `wikidata_get_entity` and `wikidata_get_statements` now catch HTTP 400 (Wikidata returns `invalid-path-parameter` for syntactically valid but out-of-range IDs like `Q9999999999`) alongside 404, mapping both to the `entity_not_found` typed error ([#8](https://github.com/cyanheads/wikidata-mcp-server/issues/8)).
