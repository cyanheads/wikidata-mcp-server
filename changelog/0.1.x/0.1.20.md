# 0.1.20 — 2026-10-08

## Added

- **Singular input aliases** ([#33](https://github.com/cyanheads/wikidata-mcp-server/issues/33)) — `wikidata_get_labels` accepts `id` for `ids` and `language` for `languages`, and `wikidata_get_entity` accepts `language` for `languages`; a lone string reaches the tool as a one-element array. The advertised `inputSchema` is unchanged. Sending an array-valued `ids` or `languages` to tools whose field is a single string is still rejected.

## Changed

- **mcp-ts-core ^0.13.6 → ^0.13.14** — error results carry `data.requestId` and their text ends `(reason … · request <id>)` (0.13.10); before validation, a numeric string for a number field such as `limit` and a lone string for an array field such as `properties` are repaired (0.13.14), and `null` for an optional field is treated as absent (0.13.14); server stack traces, request context, and `rootCause` no longer reach error `data` (0.13.7, 0.13.8, 0.13.13).
- **`wikidata_get_entity` `entity_not_found` recovery hint** — "Verify the ID with wikidata_search_entities or check the Wikidata URL directly." became "Verify the ID with wikidata_search_entities or wikidata_get_labels." The tools now omit redundant recovery forwarding, since the framework fills declared hints itself; the hints callers receive are otherwise unchanged.
- **`wikidata_get_statements` `entity_not_found`** description says "this ID" instead of "this QID", because the tool accepts P-IDs too (prose change to the advertised error contract only).
- **Dockerfile** — a `deps` stage on the build platform installs production dependencies for the target architecture and prunes musl-only packages (`scripts/install-otel.ts`, `scripts/prune-musl-packages.ts`); images move to `oven/bun:1.4.2`; the healthcheck defaults `MCP_HTTP_PORT` to `3010`; `MCP_FORCE_CONSOLE_LOGGING` is no longer set.
- **`server.json`** npm entries use `runtimeHint: npx`, drop the `run` / `start:*` package arguments, and the HTTP entry sets `MCP_TRANSPORT_TYPE=http`.
- **`.env.example`** carries the current framework variables (`MCP_HTTP_MAX_BODY_BYTES`, SSE resumability, log rate limiting, failure-payload logging, per-signal OTLP endpoints) and documents `MCP_HTTP_HOST` as defaulting to `127.0.0.1`.
- **Ignore rules** — `.gitignore` and `.dockerignore` match `.env*` (`.gitignore` keeps `.env.example`, `.env.template`, `.env.sample`); `.mcpbignore` excludes `docs/idea.md`, `logs/`, `.cache/`, `coverage/`, and `tests/`.
- **CodeQL workflow** runs one job per language (`actions`, `javascript-typescript`), each uploading under `/language:<language>`.
- **`package.json`** — `files` excludes `dist/*.mcpb`; `rebuild` calls `scripts/build.ts` directly; `test` runs `vitest run`; new `start` script, and `start:stdio` / `start:http` run `node dist/index.js`; `packageManager` is `bun@1.4.2`.
- **README badges** show MCP SDK `^2.2.0` and Bun `1.4.2+`.
- **`CLAUDE.md` / `AGENTS.md`** synced to the current framework template; the Publishing section declares the gated release PR mode.
- **Development tooling** — `scripts/` (`devcheck`, `lint-mcp`, `lint-packaging`, `release-github`, `check-skill-versions`, `check-framework-antipatterns`), `framework-skills/`, the feature-request issue template, and `devcheck.config.json` (empty `outdated` allowlist) synced to the framework scaffold.
