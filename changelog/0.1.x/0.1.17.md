# 0.1.17 — 2026-07-14

## Added

- **`kind` / `sections` / `retrieval_notice`** — new output fields on `wikidata_get_entity` and `wikidata_get_statements`. An oversized response now returns `kind: "outline"` with the available sections and their byte sizes, largest first, instead of a payload past the calling client's token limit — `wikidata_get_statements` on Q30 (467 properties, 1,717 statements) drops from 519,077 to 13,893 bytes ([#17](https://github.com/cyanheads/wikidata-mcp-server/issues/17)).

## Changed

- **`wikidata_get_entity`** — `fields` now forwards to the REST API's `?_fields=` parameter (`WikidataRestService.fetchEntity()`), narrowing the upstream fetch instead of fetching the full entity and filtering client-side. `Q76` with `_fields=labels` is 6,703 bytes over the wire versus 344,114 whole ([#26](https://github.com/cyanheads/wikidata-mcp-server/issues/26)).

## Fixed

- **`WikidataSparqlService.prepareQuery()`** — the label `SERVICE` injection regex now recognizes a trailing SPARQL `VALUES` clause, so a query ending in `} VALUES ?x { wd:Q5 }` no longer gets the `SERVICE` block injected inside the `VALUES` data block, which produced a parse error ([#20](https://github.com/cyanheads/wikidata-mcp-server/issues/20)).
