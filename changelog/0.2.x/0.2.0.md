# 0.2.0 — 2026-10-13

## Added

- **`wikidata_get_statements` value types** — property, lexeme, form, sense, and entity-schema values come back as `{ type: 'entity-id', entityType, id }` ([#43](https://github.com/cyanheads/wikidata-mcp-server/issues/43)); quantities carry `upperBound` and `lowerBound` ([#44](https://github.com/cyanheads/wikidata-mcp-server/issues/44)); unknown and explicitly absent values come back as `{ type: 'somevalue' }` / `{ type: 'novalue' }` instead of being dropped ([#39](https://github.com/cyanheads/wikidata-mcp-server/issues/39)).
- **`invalid_search_parameter`** on `wikidata_search_entities` — an upstream 400 (in practice a language the search endpoint does not support, such as `mul`) returns this error with a recovery hint instead of a raw fetch failure ([#42](https://github.com/cyanheads/wikidata-mcp-server/issues/42)).

## Changed

- **Breaking: `wikidata_get_statements` references are grouped by source** ([#38](https://github.com/cyanheads/wikidata-mcp-server/issues/38)) — `references` is now `[{ parts: [{ property, value }] }]`, one entry per upstream reference in upstream order, where it was a flat list of parts. `labelsResolved` is `false` on an outline.
- **Breaking: `wikidata_sparql_query` accepts SELECT only** ([#29](https://github.com/cyanheads/wikidata-mcp-server/issues/29)) — ASK, CONSTRUCT, DESCRIBE, updates, and plain text are rejected with `not_select_query` before the request is sent (ASK previously crashed with an internal error).
- **Breaking: `wikidata_sparql_query` responses are held to 64,000 UTF-8 bytes** ([#28](https://github.com/cyanheads/wikidata-mcp-server/issues/28)) — a larger result returns its leading rows, cut between whole rows, with `returnedCount`, `totalCount`, and a `notice` to page with `ORDER BY` plus `LIMIT`/`OFFSET`.
- **Breaking: language inputs are validated** ([#36](https://github.com/cyanheads/wikidata-mcp-server/issues/36)) — `language` / `languages` on every tool take Wikidata language codes, case-insensitive with `_` read as `-`. A blank value means `en` (it no longer suppresses labels), and an invalid code is rejected. `wikidata_sparql_query` `language` also takes a comma-separated fallback list (`fr,en`).
- **`content[]` carries the data `structuredContent` carries** ([#28](https://github.com/cyanheads/wikidata-mcp-server/issues/28)) — `wikidata_get_entity`, `wikidata_get_labels`, `wikidata_get_statements`, `wikidata_get_sitelinks`, and `wikidata_sparql_query` render every language, statement, sitelink, and row instead of a sample.
- **`wikidata_get_labels` `openWorldHint`** is `true` ([#31](https://github.com/cyanheads/wikidata-mcp-server/issues/31)).
- **Response sizes are measured in UTF-8 bytes** — the outline decisions on `wikidata_get_entity` and `wikidata_get_statements` and the SPARQL budget count bytes, not UTF-16 code units, so CJK-heavy results no longer pass at up to three times the budget.
- **Dockerfile** image tags move to `oven/bun:1.4.3`.
- **`framework-skills/`** synced to the current framework release.

## Fixed

- **`wikidata_get_statements` labels** ([#30](https://github.com/cyanheads/wikidata-mcp-server/issues/30), [#37](https://github.com/cyanheads/wikidata-mcp-server/issues/37)) — item QIDs in qualifiers and reference parts, and quantity units, resolve to labels (`unitLabel`) instead of rendering as bare QIDs or entity URIs.
- **`wikidata_get_statements` overflow check** ([#40](https://github.com/cyanheads/wikidata-mcp-server/issues/40)) — the outline decision is made before any label lookup, and label batches run at most four requests at a time.
- **`wikidata_sparql_query` parse errors** ([#34](https://github.com/cyanheads/wikidata-mcp-server/issues/34)) — reported line numbers refer to the caller's query, not the prefixes and label SERVICE the server injects.
- **Multilingual labels** ([#41](https://github.com/cyanheads/wikidata-mcp-server/issues/41)) — the injected label SERVICE ends its language list with `mul`, and `wikidata_resolve_external_id` falls back to the `mul` label.
- **Language injection** ([#36](https://github.com/cyanheads/wikidata-mcp-server/issues/36)) — a `language` containing a quote can no longer rewrite the SPARQL text of `wikidata_resolve_external_id` or the label SERVICE.
